Week 5 — A/B 프롬프트 구조화 실습 발표

커피 배달 게임
프롬프트 구조화 A/B 비교

같은 커피 배달 게임을, 구조화하지 않은 요청(A)과
구조화된 요청(B)으로 각각 수정해본 비교 실험

실험 설계

A / B는 무엇이 다른가

A 구조화 없음
  • CLAUDE.md(system prompt) 없음
  • 다른 대화창에서 자유롭게, 생각나는 대로 중국어로 요청
  • "무엇을 바꾸지 말아야 하는지"는 한 번도 명시하지 않음
B 구조화함
  • CLAUDE.md를 system prompt로 고정
  • 매 요청마다 [현재 상황]/[목표]/[구체적 변경]/[유지할 것]/[완료 기준] 5단 구조
  • 버그 수정은 [문제 재현]/[실제 결과]/[기대 결과]/[수정 범위] 형식 사용

※ A와 B 모두 같은 모델(Claude Sonnet 5)과 같은 언어(중국어)로 대화했고, B는 A가 만든 결과물을 이어받아 계속 개발했습니다.

대비 1

관(레벨)당 잔 수 — 세 번 고친 A, 한 번에 끝난 B

A 세 번 수정, 그래도 오해
现在，重新设计关卡数，从现在的144杯改成88杯。

"144잔→88잔"으로 잔 수를 줄이고 싶다는 의도만 전달 → 적용 범위를 안 써서 AI가 "8관만 88잔, 7관은 89잔"이라는 이상한 규칙을 만듦.

B 계산식 + 예시 숫자로 한 번에
관 = 이웃 수 × 라운드로 계산 1~4관: 1라운드 / 5관부터: 2라운드 예) 이웃 4명 → 1관은 4잔

계산 규칙과 구체적 예시 숫자를 함께 줘서 모호함 없이 한 번에 의도대로 구현됨.

대비 2

문제가 생겼을 때 어떻게 말하는가

A 결과만, 설명 없이
失败的请、再次尝试 (실패한 요청, 다시 시도)

무엇이 실패했는지, 어떤 결과를 원하는지 설명이 없음. "让我尝试一下"(내가 해볼게)도 새 지시로 오해되어 다시 정정해야 했음.

B 고정된 4단 형식
[문제 재현] 시작→커피 받기→배달 [실제 결과] 말풍선은 나오나 하트 없음 [기대 결과] 하트가 2~3초 나타났다 사라짐 [수정 범위] 하트만 수정

AI가 그리기 순서 버그(하트가 배경에 가려짐)를 정확히 찾아내고, 원인도 설명받음.

대비 3

결과를 어떻게 확인하는가

A 매번 직접 물어봐야 함
给我打开看看 结束了吗?

AI가 스스로 완료 여부·확인 내용을 보고하지 않아, 사용자가 "열어봐", "끝났어?"를 반복해서 물어야 했음.

B system prompt가 보고 형식을 고정
CLAUDE.md 산출물 규칙: 마지막에 [변경한 점 / 직접 확인한 것 / 미확인] 세 가지로 짧게 정리한다.

채팅창에서 따로 요청하지 않아도, 매 요청마다 자동으로 변경/확인/미확인 형식 보고가 따라옴. (= 채팅 prompt가 아니라 system prompt의 효과)

B의 한계

구조화해도 남는 문제들

① 트레이 "×숫자"

사용자가 직접 "넘치면 옆에 ×숫자로 표시"라고 설계해서 지시 → 구현은 됐지만 실제로 보니 시스템 알림처럼 보여 마음에 안 들었음. 구조화는 요구사항 누락은 막지만, 아이디어 자체가 별로일 수 있다는 건 못 막음.

② 충돌(통과 금지) 1차 누락

1차 prompt: "모두 막아달라"고만 쓰고 개체별 확인 방법은 안 씀 → 일부만 반영됨. 2차에서 "개체별 전수 목록 + 표로 보고"를 요구한 뒤에야 전부 수정됨.

결론

무엇이 도움이 됐고, 다음엔 무엇을 더 쓸까

도움이 된 조건 — [유지할 것](불변 조건)을 매번 명시, 계산식·확률·숫자를 구체적 예시와 함께 전달, 버그는 [문제 재현/실제 결과/기대 결과/수정 범위] 형식, system prompt(CLAUDE.md)로 보고 형식을 고정.
아직 남은 문제 — "무엇을 넣을지"는 적어도 "어떻게 생겼는지"는 안 적으면 AI가 임의로 디자인함(장식 외관 등). "완료했다"는 보고 후에도 실제 플레이해보면 빠진 부분이 발견됨.
다음에 더 쓸 조건 — 기능뿐 아니라 스타일/수치/확률까지 구체화하기, "완료" 보고를 받은 뒤에도 직접 플레이해서 재확인하는 절차를 prompt에 포함시키기.
